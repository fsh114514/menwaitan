## 2. 后端改动点逐条（`app/api/chat/route.ts`）

### A1 —— 新增可见性内核与 v2 常量

**位置**
- 常量区：`route.ts:34-38`（`roundRules` 之后，`// ROUND_FN_END` 前后）
- 工具函数区：`route.ts:200`（`export async function POST` 之前）

**现状**：文件里没有任何「可见性」概念；`history` 是纯线性数组，所有发言人对它一视同仁（`route.ts:225-231`）。

**改成什么**

```ts
// ---- v2 信息层 ----
type Vis = { kind: "public" } | { kind: "private"; to: string };
type RawMsg = { role: string; who?: string; whoId?: string; content?: string; vis?: Vis | string };

/** 这条发言对 viewerId 是否可见。缺省/异常一律视为 public（旧存档兼容）。 */
function isVisibleTo(m: RawMsg, viewerId: string): boolean {
  const v = m.vis;
  if (!v || v === "public") return true;
  if (typeof v === "string") return v === "public" || v === viewerId;   // 防御：有人直接传 id 字符串
  if (v.kind === "public") return true;
  if (v.kind === "private") return v.to === viewerId || v.to === "user";
  return true;
}

/** 按 viewer 过滤 + 保留现有 debate 前缀逻辑（原 route.ts:225-231）。 */
function buildHistoryFor(viewerId: string, messages: RawMsg[], mode: string, intl: boolean) {
  return messages
    .filter((m) => isVisibleTo(m, viewerId))
    .map((m) => ({
      role: m.role === "assistant" ? "assistant" : "user",
      content:
        mode === "debate" && m.role === "assistant" && m.who
          ? (intl ? m.who + ": " : m.who + "说：") + String(m.content ?? "")
          : String(m.content ?? ""),
    }));
}

const INFO_LAYER_ZH = "\n\n【信息差】你只能看到上面这些发言。别人私下说过什么、你不在场时发生的事，你都不知道——绝不假装知道。如果你的判断依赖于你不掌握的信息，就直接说你不知道，或者当场追问。";
const INFO_LAYER_EN = "\n\n[Information asymmetry] You only have the statements above. Whatever was said privately to others, or while you were out of the room, you do not know — never pretend to. If your judgement depends on information you lack, say so plainly, or ask on the spot.";
const SUMMON_ZH = (roster: string) => "\n\n【可点名】在座者及其 id：" + roster + "。如果你认为其中某人必须当场对质，请在你回答的**最后单独一行**输出 [[call:<id>]]（只输出这一行，别加解释）。只在你真要当面对峙时才输出；对方会在下一轮最先发言。不点名就完全不要出现这个标记。";
const SUMMON_EN = (roster: string) => "\n\n[Call-out] At the table: " + roster + ". If someone must be confronted right now, put [[call:<id>]] alone on the FINAL line of your reply. Use it only for a real confrontation; they will speak first next round. Otherwise never output that token.";
const SUMMON_RE = /\[\[\s*call\s*:\s*([A-Za-z0-9_-]+)\s*\]\]/;

/** 返回剥离后的文本 + 合法目标 id；目标非法时视为未点名。 */
function extractSummon(text: string, valid: Set<string>, selfId: string): { text: string; target: string | null } {
  const m = SUMMON_RE.exec(text);
  if (!m) return { text, target: null };
  const id = m[1];
  const clean = text.replace(SUMMON_RE, "").replace(/\n{3,}/g, "\n\n").trimEnd();
  if (!valid.has(id) || id === selfId) return { text: clean, target: null };
  return { text: clean, target: id };
}

const WHISPER_MARK_ZH = "【私下只告诉你的话，别人听不到】\n";
const WHISPER_MARK_EN = "[Said to you in private — nobody else can hear this]\n";
```

**牵连影响**
- 纯新增，不触碰对谈 / 双语 / SSE。`buildHistoryFor` 只有在 A3 接线后才生效。
- `SUMMON_*` 只在圆桌分支使用（A9），对谈模式不加。
- 注意：`SUMMON_RE` 用了 `g` 会带 `lastIndex` 状态，**不要在函数外用 `.test()`**；上面用 `exec` + 字符串 `replace`，安全。

**回归测试点**
- 未传 `vis` 的老消息（`messages` 里全是旧格式）→ `buildHistoryFor` 输出必须与改造前 `route.ts:225-231` **逐字符一致**（可临时打日志对比）。

**风险与坑**
- `vis` 是前端可控字段，服务端必须把它当作**不可信输入**做形状校验（至少 `to` 必须在 `selected` 白名单内），否则用户能伪造成「只有某某能看见」的任意发言。

### A3 —— `history` 改成按 viewer 过滤（**v2 的心脏**）

**位置**：`route.ts:225-231`

**现状**

```ts

  role: m.role === "assistant" ? "assistant" : "user",
  content:
    mode === "debate" && m.role === "assistant" && m.who
      ? (intl ? m.who + ": " : m.who + "说：") + String(m.content ?? "")
      : String(m.content ?? ""),
```

这是一个**模块级的共享可变数组**，`route.ts:350` 每轮 `history.push(...)` 往里塞，所有发言人读同一份。

**改成什么**

```ts
// 保留一条「原始消息」列表（可变，供轮内追加），每次给某个发言人组装 prompt 时再过滤
const rawHistory: RawMsg[] = (Array.isArray(messages) ? messages : []).map((m: any) => ({
  role: m.role === "assistant" ? "assistant" : "user",
  who: typeof m.who === "string" ? m.who : undefined,
  whoId: typeof m.whoId === "string" ? m.whoId : undefined,
  content: String(m.content ?? ""),
  vis: m.vis,                       // 原样带过来，isVisibleTo 负责兜底
}));
```

调用点（原 `route.ts:312` / `318`）改为：

```ts

const debateContext = buildHistoryFor(speaker.id, rawHistory, mode, intl);   // 圆桌
```

> ⚠️ 原 `route.ts:318-325` 的 `debateContext` 里那段「从 `X说：` 反解角色、再按 intl 换名」的逻辑，要**搬进 `buildHistoryFor` 的 map 之前或之内**（因为它依赖 `who` 展示名）。建议把 `route.ts:318-325` 那段整体保留在圆桌循环里，只是把它的输入从 `history` 换成 `buildHistoryFor(...)`：

```ts

  const mm = /^([^\s：:]+)说[：:]\s*/.exec(m.content);
  if (m.role === "assistant" && mm) {
    const meta = getMeta(mm[1]);
    return { ...m, content: (intl ? (meta?.name || mm[1]) + ": " : (meta?.zhName || mm[1]) + "说：") + m.content.slice(mm[0].length) };
  }
  return m;
});
```

**改成什么（悄悄话对自己的标注）** —— 在 `buildHistoryFor` 里补一条，让被私聊的人知道「这是私下的」：

```ts
// 插在 map 的 content 计算之前
if (m.vis && typeof m.vis === "object" && m.vis.kind === "private" && m.vis.to === viewerId) {
  return { role: "user" as const, content: (intl ? WHISPER_MARK_EN : WHISPER_MARK_ZH) + String(m.content ?? "") };
}
```

**牵连影响**
- **对谈模式（`selected.length === 1`）**：只剩一个 viewer，`isVisibleTo` 对 public 全放行；只有当用户曾对别人悄悄话（此时在座者已变）才会有差异。要保证「在座一人 + 历史里存在发给已离席者的悄悄话」不会让模型突然看到 `【私下…】` 标记而困惑——建议 viewer 不在 `selected` 的 private 消息一律按 public 放行？**不**：更安全的做法是**保持过滤**（离席者本就不该在场），但要加回归用例覆盖。
- **双语（intl / lang）**：`buildHistoryFor` 接收 `intl`，前缀逻辑与原实现逐字一致；`WHISPER_MARK_*` 分中英两版，别混。
- **SSE**：本改动不产生新事件。
- **`send()` 事件类型**：无关。

**回归测试点**
1. 全部 public 时，`buildHistoryFor(id, rawHistory, "debate", false)` 输出 == 改造前 `history`。
2. 仅「甲可见」的发言：`buildHistoryFor("甲", …)` 含它，`buildHistoryFor("乙", …)` 不含它。
3. `vis` 为 `undefined` / `"public"` / `{kind:"public"}` 三种形状都放行。
4. `mode === "chat"` 时 assistant 消息不加 `X说：` 前缀（保持 `route.ts:228` 的 `mode === "debate"` 条件）。
5. `intl === true` 时前缀是 `X: ` 且 `who` 用的是 `meta.name`（英文清洗名）。

**风险与坑**
- `history` 原本既是「输入」又是「输出缓冲」（`route.ts:350` push）。改完后要**明确区分** `rawHistory`（含本轮新增）与「组装给模型的 messages」。漏改任何一处 `history` 引用 → 悄悄话泄漏给全场。

### A5 —— `streamOnce()` 首行暂存（方案 B，可选）

**位置**：`route.ts:270-283`

**现状**

```ts
const streamOnce = async (prompt: any[], guard: boolean): Promise<{ text: string; cjk: boolean }> => {
  const res = await call(prompt);
  let text = "";
  let cjk = false;
  for await (const chunk of res) {
    const delta = chunk.choices?.[0]?.delta?.content || "";
    if (!delta) continue;
    text += delta;
    if (CJK_RE.test(delta)) cjk = true;
    if (guard && cjk) return { text, cjk: true };
    send({ type: "delta", text: delta });        // ← 逐字外发，无法回收
  }
  return { text, cjk };
};
```

**改什么**：把 `[[call:id]]` 约定放在**回答最开头**时，`streamOnce` 可以先攒住直到见到第一个 `\n`，判定首行是不是标签，再决定外发内容：

```ts
const streamOnce = async (prompt: any[], guard: boolean, holdFirstLine = false) => {
  // ... 同上 ...
  let held = "";
  let released = !holdFirstLine;
  const flush = (s: string) => { if (s) send({ type: "delta", text: s }); };
  for await (const chunk of res) {
    const delta = chunk.choices?.[0]?.delta?.content || "";
    if (!delta) continue;
    text += delta;
    if (guard && CJK_RE.test(delta)) return { text, cjk: true };
    if (!released) {
      held += delta;
      const nl = held.indexOf("\n");
      if (nl >= 0) {
        const first = held.slice(0, nl);
        const rest = held.slice(nl + 1);
        released = true; held = "";
        if (!SUMMON_RE.test(first)) flush(first + "\n");
        flush(rest);
      } else if (held.length > 64) {         // 兜底：超长首行，直接放行
        released = true; flush(held); held = "";
      }
    } else flush(delta);
  }
  if (!released && held) flush(held);
  return { text, cjk };
};
```

**关联**：`SUMMON_RE` 带 `g` 又用了 `.test()`——**必须**改成不带 `g` 的独立正则 `const SUMMON_TEST = /\[\[\s*call\s*:/;`，否则 `lastIndex` 会跨调用漂移导致偶发漏拦。

**牵连影响**
- 若采用方案 B，`prompt` 里点名纪律必须改成「放在**最开头**单独一行」。A9 的常量文案要同步改（本文档 A9 给的是「末尾」版本，二选一）。
- 英文防中文重试路径（`route.ts:293`、`297`）调用 `streamOnce` 时不要开 `holdFirstLine`，否则重试时 `reset` 与暂存冲突。
- 首字延迟增加（等第一个 `\n`）→ 体感上「啊哈」式抢答会慢一拍。

**推荐**：**先不做 A5**，采用「客户端渲染期剥离 + 服务端 `history` 剥离」的双保险（B4+B10），把 A5 当体验优化留到 v2.1。理由：改动面小、不会碰英文重试路径、验收简单。

**回归测试点（若做）**
1. 不点名时，`delta` 分片序列与改造前**逐片一致**（可以在客户端打日志比对）。
2. 点名时，前端从头到尾收不到 `[[call:` 字样。
3. 英文模式 C→中 拦截（`reset` / `EN_RETRY` / `EN_TRANSLATE`）三跳仍正常。

**风险与坑**
- 首行暂存会与 `guard` 提前 return（`route.ts:279`）交叉：提前 return 时 `held` 里可能有未外发内容。必须在 return 前 `flush(held)`，否则英文模式下会丢字。
- 别把 `holdFirstLine` 加到单人分支（`route.ts:310`）——对谈模式没有点名。

```
   A8: rawHistory.push({role:"assistant", content:<剥离后>, vis:public})
       send({type:"summon", from:"luxun", fromName:"鲁迅", target:"hayek", targetName:"哈耶克"})
   A8 循环结束（speakers 只有 1 人）→ send({type:"end"})
   B4: summonRef.current = "hayek"；插入 auto 提示「⚔ 鲁迅 点名 哈耶克…」
④ B7: r=1 → streamChat(current, null)
   B3: turnOrder=["hayek","luxun","keynes"]，whisperTo=null
   A2: speakers=[hayek,luxun,keynes]（重排后）
   A8: 哈耶克第一个发言 —— 他自己**看不到**那条 private
       （buildHistoryFor("hayek", …) 过滤掉 vis.to==="luxun" 的消息）
```

**关键验证**：哈耶克的 system prompt 里不能出现「哈耶克私下说你那套…」这句原文。

### 5.2 对谈模式（`selected.length === 1`）

- 目标条不渲染（`canWhisper === false`）。
- 走 A7 单人分支：无 `roundRules`、无 `INFO_LAYER`、无 `SUMMON`、temperature 0.8。
- SSE 只有 `who…delta…done`，然后 `end`。
- **验收：改造前后输出风格无差异。**

### 5.3 双语

- `whisper` / `summon` 事件的展示名由服务端按 `intl` 给（`route.ts:286` 同一套规则）。

## 7. 风险与坑（按严重度排序）

### 🔴 致命

1. **`Msg.who` 是显示名，不是 id**（`page.tsx:922` 取 `ev.name`；服务端 `route.ts:286` 同时发了 `who: speaker.id` 但被丢弃）。
   → 任何指向具体角色的地方（`vis.to` / `whisperTo` / `summonRef` / `turnOrder`）**必须用 id**。必须在 `Msg` 上补 `whoId`（B5）并统一契约。搞错这一条，悄悄话会发给「名字恰好等于另一个 id」的鬼角色，或者永远过滤不掉。

2. **`history` 是模块级共享可变数组**（`route.ts:225` 定义、`route.ts:350` push）。
   → 改成 `rawHistory`（原始，含 vis）+ `buildHistoryFor(viewerId)`（每次过滤）后，**必须全量替换所有 `history` 引用**。漏一处就是悄悄话全场广播。

3. **`streamOnce` 逐字外发，无法回收**（`route.ts:280`）。
   → `[[call:id]]` 会在流式过程中被用户看到。必须「服务端剥离（`extractSummon`）+ 前端渲染期剥离（B10 `showContent`）」双保险。只做服务端剥离是不够的，因为剥发生在流结束后。

4. **单人对谈分支的触发条件是 `selected.length === 1`，不是 `mode`**（`route.ts:309`）。
   → 悄悄话回合**不能**通过 `characters: [target]` 表达，否则掉进单人分支，丢失 `roundRules`/`INFO_LAYER`/`SUMMON`，点名机制直接死掉。必须走 `whisperTo` 旁路 + `solo` 变量解耦（A2/A11）。

### 🟠 严重

5. **`memeBlock` 泄漏**（`route.ts:240-251`）：只算一次却拼进所有人的 system（`route.ts:311`、`330`）。v2 之后悄悄话会通过「最后一条非 assistant 消息」变成全员场外情报。**必须在 v2 里修**（A4）。

6. **点名顺序无跨请求状态**（`page.tsx:982` 每轮一次 HTTP）。
   → 服务端**不能**用模块级 Map 记「上轮点过谁」——多用户会串台（`searchBuckets`（`route.ts:58`）已是这种写法的反面教材）。顺序必须由前端 `summonRef` 保存并回传 `turnOrder`。

7. **`/api/log` 会把悄悄话原文上报**（`page.tsx:994-1003`）。用户输入的私密内容不该进站长日志。必须脱敏（B9）。

8. **`rawHistory.push` 无 `who`**（`route.ts:350`）：轮内发言无署名，跨轮有署名（来自 `route.ts:229` 的前缀）。
   → v2 若给轮内发言补 `who`，会**改变现有观感**并影响 `route.ts:319` 的反解正则。建议 v2 **先不补**，把「署名一致性」列为 v2.1 的独立改动 + 独立回归。

### 🟡 中等

9. **token 成本上涨**：每位发言人都要过滤全量历史，秘密越多 prompt 越大（12 条存档 × 多轮 × 多人）。要在 A4 之后实测单次请求体量与首字延迟。

10. **`roster` 拼进 system 会显著加长 prompt**（A9），12 人时尤其明显。建议 `selected.length > 6` 时关闭点名，或 roster 只列 id + 短名。

11. **名字反解正则脆弱**（`route.ts:319` `^([^\s：:]+)说[：:]\s*`）：只要 `Msg.who` 里出现空格或全角冒号，反解就失败 → 该条发言在 intl 下不会被换名。v2 不修，但**别在上面加更多依赖**。

12. **`I18N` 两侧必须同时补键**（`page.tsx:99-379`），否则 TS 报错或另一语言下显示 `undefined`。

13. **`charById` 的 TDZ**（`page.tsx:632` 声明）：任何在 `page.tsx:632` 之前使用它的派生值都会 ReferenceError（`const` + TDZ）。`whisperTarget` 要在渲染区算（B2 已标注）。

14. **`rounds` 语义变化**：悄悄话回合占掉 `rounds` 的第 1 轮。若用户设 `rounds=1`，一条私聊就只有一个人回话，用户可能以为「程序坏了」。**必须在目标条上给出明确文案**（`whisperHint`）。

15. **`summon` 事件与 `pushLive` 的时序**（`page.tsx:921`）：下一位发言人的 `who` 会固化上一位的 `live`。所以服务端必须**在下一轮 `ask` 之前**发 `summon`（A8 已保证），否则 `⚔` 提示会插错位置。

### 🟢 轻微

16. `key={i}`（`page.tsx:1225/1229`）用索引：插入 `auto` 消息会让后续 key 漂移。改用 `m.mid || i` 更稳，但要确认不破坏 `animationDelay` 的入场动画（`page.tsx:1229`）。

17. `ESCALATE_WORDS` / `maybeEscalate`（`page.tsx:53`、`844-859`）对悄悄话同样生效 —— 这是**有意为之**，写进验收，别当 bug 修。

18. `SavedChat` 没有 schema 版本号（`page.tsx:97`）。v2 靠「缺省即 public」容忍，暂不需要迁移代码；但若将来加 speaker→speaker 私聊，就必须加 `v` 字段。

19. 前端 `selected` 在 `send()` 的异步循环期间可能被用户拖动改变 → 顺序抖动（现存问题）。建议 `send()` 开头 `const seated = [...selected]` 快照。

20. 服务端 `temperature`（`route.ts:258`）按 `selected.length === 1` 分流 0.8 / 0.85。悄悄话回合在座 ≥ 2 → 0.85，符合预期，不用改。但若产品希望「私房话更收敛」，可在此处按 `whisperTo` 单独给 0.75。

## 8. 明确不做（v2 范围外，避免膨胀）

- ❌ 发言者 → 发言者的私下对话（`vis.to` 指向另一个角色）。数据结构已支持（`Msg.vis` + `mid`），但 v2 只做「用户 → 角色」。
- ❌ 发言者的私下回复（`role:"assistant"` + `vis.kind === "private"`）。留接口不做。
- ❌ 前端隐藏私聊内容（用户是全知观众，必须看得见自己的悄悄话）。
- ❌ 数据库/服务端会话状态（一切靠前端全量重传 `messages`，无状态设计不能破）。
- ❌ 轮内发言补 `who` 署名（风险 8，留 v2.1）。
- ❌ `streamOnce` 首行暂存（A5，方案 B）—— 先用 B10 的渲染期剥离兜底。
- ❌ 点名并发/连点（一轮只解析第一个 `[[call:]]`）。

### B.2 既有实现里仍然敞着的洞（按严重度）

1. **🔴 `memeBlock` 泄漏未修**（本文档 A4）。
   `route.ts:302-308` 仍以「最后一条非 assistant 消息」为触发源，只算一次，却拼进**全部三个分支**的 system（`381` / `401` / `425`）。

   修法：触发源过滤成「仅 public 消息」，见 A4。**一处 3 行改动。**

2. **🔴 人名子串点名会大量误触发**（替代 A10 的方案）。
   `queue.findIndex((s) => text.includes(s.zhName) || (!!s.name && text.includes(s.name)))`：
   - 哈耶克说「凯恩斯主义」→ 命中 `凯恩斯` → 凯恩斯被拉到队首；
   - 中文模式下 `s.name`（英文名）也会参与匹配，跨语言误命中；
   - 引用他人话语（「正如鲁迅所说」）同样触发。
   → 建议改为**显式协议**：要么用模型标签（本文档 A6/A9/A10，需双端剥离，见 §7 风险 3），要么把条件收紧为「`@` + 人名」或「人名 + 质问类动词」。当前实现在 demo 里会显得「随机拉人」。

3. **🟠 悄悄话原文进 `/api/log`**（本文档 B9 未做）。用户输入的私密内容流向站长后台。

4. **🟠 悄悄话把 `rounds` 压成 1**（B7 走了不同语义）。
   `rn = … ? 1 : rounds` → 用户设 4 轮，私聊后**只剩 1 轮**，圆桌交锋消失。叠加「同轮内点名提前」，用户实际只看到：「A 的私聊回复 + 被拉者的一句话」。与 v2 想要的「点名之后整桌重新交锋」有落差。建议改成 `r === 0` 单发言、后续轮照常（本文档 B7 原方案）。

5. **🟡 死变量可能让 `npm run lint` 变红**：`route.ts:293` 的 `const history = visibleHistory(selected[0]?.id || "");` 已无引用（仅此一处 grep 命中），注释写着「兼容旧引用」但调用点都换成了 `visibleHistory(...)`。`eslint-config-next` 默认带 `no-unused-vars` 规则，建议直接删。
