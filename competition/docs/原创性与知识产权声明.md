## 三、本届新增内容（v2：信息层机制）

### 3.1 与 v1 的实质差异

v1 的圆桌形态，本质上是**"多个角色共享同一份完整对话上下文、轮流发言"**——所有参与者看到的信息完全相同。后果是：角色之间因为"知道的都一样"，容易互相附和、逐渐趋同，形成"伪共识"，辩论的信息增量随时间迅速衰减。

**v2 的核心改动，是在圆桌之下加一层"信息层"（Information Layer），即"谁知道什么"**：发言者不再共享同一份历史，而是**各自只能看到自己该看到的信息**。于是"信息不对称"从需要消除的缺陷，变成了驱动讨论的机制。

本章内容对应 v2 的**已实现部分**（参赛版本 0.2.0，实现于 2026-10-17）。核心代码位于 `app/api/chat/route.ts`（信息层段落）与 `app/page.tsx`（"私"开关、悄悄话状态条、消息可见性标记）；详细改动清单见 `competition/docs/00-v2改动清单.md` 与仓库 `CHANGELOG.md`。

### 3.2 已实现的三个机制

#### 机制一：发言可见性（Per-speaker Visibility）

- 对话中的每一条发言都带可见性标记：`public`（全桌可见）或"仅某一位可见"。
- 服务端在为某位发言者生成回复时，**只把"他看得见的历史"喂给他**；他看不到的内容不会出现在他的上下文里。
- 机制意义：这是信息层的地基——**别人能看到你说了什么，但看不到你为什么这么说**，天然制造理解落差与追问动机。

#### 机制二：悄悄话（Whisper）——单向私下信道

- 已入席的人物卡片上提供「私」开关。用户可以**单独**对某一位思想家说话，**桌上其他人完全看不到这条消息**；对话流中该消息以红色虚线左边框与"私下说的 — 只有 X 看得到"明确区分。
- 服务端为悄悄话消息打上「有人私下对你说，桌上其他人听不到」标记，并向该角色追加行动指令：**基于这条信息采取行动**（点名、对质、改变立场），但**不许暴露"私下"这件事本身、不许复述原话**。
- 机制意义：把信息不对称变成用户可操作的玩法——用户手里握着一张别人没有的牌。

#### 机制三：点名拉人对峙（Summon to Confrontation）

- 圆桌的发言顺序由**固定循环改为可变队列**：当某位发言者在发言中点名了另一位在座者，**被点名者会被提到队首、紧接着发言**，形成"当面对质"的效果。
- 点名识别做了边界校验（名字之后不可紧跟汉字），避免"凯恩斯主义""孔子学院"这类词造成误触发。
- 机制意义：**发言顺序由讨论内容动态决定**，而不是开场前固定好的名单——用户的一句悄悄话可以真实改变公开讨论的走向。

### 3.3 其他 v2 改动

- **信息层系统提示**：向所有角色注入"信息层"规则，使其意识到"这张桌上每个人知道的并不一样"，并可以被自己掌握的信息驱动行动。
- **接口向后兼容**：`POST /api/chat` 新增可选字段 `whisperOnly`（本轮只让指定人物回应）与消息级 `whisperTo`（该条仅对目标人物可见）；**不传新字段时行为与 v1 完全一致**。
- **修复 v1 的发言人缺失问题**：v1 在同一轮里把发言写入共享历史时没有带发言人，导致同轮内后发言的人不知道前一句是谁说的；v2 修正为带显示名。
- **隐私处理**：悄悄话原文不写入服务端日志，只落一条标记（`[whisper — content not logged]`）。
- **验证**：`tsc --noEmit` 通过、`next build` 通过（8 个路由正常生成）。

### 3.4 本届团队（本人）在 v2 中的贡献

- 提出"信息层"整体设想与上述机制的**具体形态**（谁对谁说什么、什么信息可见、发言顺序如何被改变）；
- 设定机制的**产品目标与边界**：以"讨论持续产生新信息"为成功标准，而非"角色吵架好看"；
- 决定 v2 与 v1 的**兼容关系**：保留 v1 的对谈／圆桌作为基础形态，信息层作为可选增强、不破坏原有行为；
- 确定**实现路径与成本控制原则**（在有限的免费模型额度下仍可用）；
- 完成验收：逐项实机验证悄悄话不可见性、点名触发与向后兼容。

### 3.5 尚未实现／开发中的部分（如实说明）

- **"以信息新颖度作为停止判据"目前尚未实现**。该机制的**设计构想由本人提出**：讨论何时结束不按"聊够几轮"或"是否达成一致"判断，而是判断**是否还在产生新信息**——对每轮发言做文本片段切分（Unicode shingle）与新颖度估算，当新增信息占比低于设定阈值、且没有新证据输入时，判定"讨论已无新信息"并自动收束。
- 该项当前处于**设计完成、尚未编码**的状态；若在提交前完成实现与验证，将据实更新本节并补充代码位置与验收方式。
