### 0.2 ✅ 前端已经接好了 —— 不要再去改代码

> **本节原稿写的是"前端完全没接，需要补 6 步"。那份判断已经过期**：写脚本时前端确实还没接，
> 但在同一晚已经实现、验证并提交（提交 `0bc0458`、`d7c8039`）。**下面是现在真实存在的 UI，
> 录屏时照着找就行，不需要任何开发工作。**

**怎么用（真实交互，三步）：**

1. 点**输入框左侧的「私下说」按钮**（主入口）→ 弹出在座人物清单 → 选一个人。
   选中后按钮会**变成红底并显示对方名字**（如「密 鲁迅」（一个红色小方章里一个「密」字））。
   也可直接点**人物卡片上的小方块「私」**作为快捷方式。
2. 输入框上方出现一条**红色虚线状态条**：
   > 〔密〕 正在私下对 **鲁迅** 说话 —— 桌上其他人看不到　　　[取消]
   此时输入框的提示文字会从「抛出一个议题，让思想家们交锋…」变成「**私下说点什么…**」。
3. 打字、回车发送。这条消息在对话流里会显示成**深色气泡 + 红色虚线左边框**，顶上有一行小字：
   > 〔密〕 只有 **鲁迅** 看得到

   发送后**会自动接一轮公开圆桌**，期间输入框上方换成一条琥珀色状态条：
   > 〔场上〕（红条反白）桌上正在反应 —— 你私下说的那件事，被人摆到台面上了

**技术契約（已实现，供说明文档引用，录屏时不需要管）：**

```
POST /api/chat
body.whisperOnly: "luxun"        // 这一轮只让这个人回应（桌上其他人仍在席）
body.messages[] 里每条 user 消息可带：
  whisperTo: "luxun"             // 只有鲁迅看得见；不传 = public
assistant 消息一律 public（后端强制）——别人看得到你说了什么，看不到你为什么这么说
```

**已验证的行为（用真实模型跑过，不是推测）：**
- 发悄悄话时，一次请求只产生 **1 个 `who` 事件**——只有当事人回应，其余在座者不发言
- 当事人下一轮**真的会当众点名**对方（实测：鲁迅从"学外语的意义…"变成"乔布斯曾言…我却问你…"）
- 被点名者**不再以「我同意」开场**，改为正面接火（这是 v2 后加的"被点名→接火"机制）
- 悄悄话原文**不进 `/api/log`**，也不会被查梗检索当成"场外情报"注入所有人

> **红线（仍然适用）**：可见性必须是**服务端真过滤**——这一点已经做到（`visibleHistory(speakerId)`
> 按 `vis` 过滤后才进 prompt）。**绝对不要只在 UI 上把气泡藏起来假装信息不对称。**

### 2.1 旁白录制方案（两条路，选一条）

#### 方案① 自己录（**推荐**）

**为什么推荐**（按重要性排）：
1. **重音只有人能给。** 这稿里有「看到没？」「重点来了」「可没人陪我辩」这种口语转折，TTS 一律平读，钩子的力道直接没一半。
2. **和作品调性一致。** 门外谈是"纸墨红 + 文火慢炖"的东西，一个真实大一学生的声音，比播报腔的机器声更贴。你在校宣传部报道组剪过片子，这活儿本来就熟。
3. **评委听得出来。** 评审要看几十份作品，TTS 的平铺直叙几乎一听就知。这不是致命伤，但会让人觉得"不用心"——在"原创贡献"这一项上尤其吃亏。

**怎么做：**
- **设备**：先用你自己的手机（iPhone 语音备忘录就够），或几十块的领夹麦。**别用笔记本内置麦**（键盘声 + 风扇声）。
- **环境**：衣柜里、挂满衣服的房间、蒙着被子的角落——目标是**没有回响**。录音前先录 10 秒静音，回放听有没有空调/冰箱底噪。
- **位置**：话筒离嘴 **15–20 cm**，**偏 15°**（不正对，防喷麦）。稿子打印出来或用另一台设备看，别让纸挡在嘴边。
- **念法**：**边看画面边念**（把分镜表放旁边）。每句录 2 遍；读错就停下来，从**那一句**重读，别整段重来。语速压到 210–225 字/分——比你以为的慢。
- **后期（剪映）**：人声轨 →「降噪」打开（强度别拉满，拉满会发闷）→「响度统一」→ EQ 把 **200 Hz 以下**切一点（去浑浊），**2–4 kHz** 提 2–3 dB（提清晰度）。**不加混响**，报纸风要干净。
- 降噪后如果声音发闷：**回去重录**，别靠软件硬救。

#### 方案② 用 TTS 生成（保底方案）

**首选工具：剪映自带「文本朗读」**——理由：音色和字幕、时间轴在同一个工具里，改稿成本最低（旁白稿一改直接重生成），且剪映音色可商用。
- 音色建议：**低沉男声 / 纪录片解说类**（"解说小帅""沉稳男声"一类），**不要**用甜美播报女声。
- 次选：Edge 浏览器「大声朗读」的 `zh-CN-YunxiNeural`（云希，自然偏温和）或 `zh-CN-YunjianNeural`（云健，更有力），录系统声导出。
- 不推荐自己搭 Fish / IndexTTS 之类——除非你愿意为调参花掉半天。

**TTS 的 4 个坑，逐条避：**
1. **停顿控制**：TTS 在「。」处停得过长。改稿时**多用「，」「——」「、」，少用句号**（本稿的 `[停]` 标记就是给 TTS 用的，直接替换成「，」）。
2. **专有名词**：把 `outgate.chat` 写成 **「outgate 点 chat」**，`Next.js` 写成「Next J S」，`SKILL.md` 写成「skill 点 M D」——否则会读成乱码。`AI` 一般读得对，念完抽听一句。
3. **语速**：TTS 默认偏快且平。导入剪映后把语速设 **0.95×**，并把 4-7、8-1 这种关键句**手动切开、中间插 0.4 秒静音**。
4. **必须量时长**：TTS 语速固定，最容易超时。**导出的旁白音频总时长必须 ≤ 4:12**，超了就删句，别硬挤画面。

#### 我的建议

**自己录。** 除非你不愿意让自己的声音出现在作品里——那就用剪映「文本朗读」的低沉男声，也完全可接受。**两条路都不要用"AI 播报"感的女声**，会和报纸风打架。

## ③ 演示场景剧本：圆桌 + 悄悄话

> 这一章是给"录屏那 100 秒"用的操作剧本。左列是**你要做的动作**，右列是**预期屏幕上会发生的**。AI 输出不完全确定，所以每段都给了"不按预期走怎么办"。

### 3.1 为什么选这三位

| 人物 | id | 立场 | 在议题里的角色 |
| --- | --- | --- | --- |
| **鲁迅** | `luxun` | 批判 / 国民性 | **"专业值不值得读"这个话题的天然主角**——他不会给安慰，先反问你凭什么这么问。说话直、不留情面 → 最适合被"递刀"后当众点名 |
| **马克思** | `marx-skill` | 历史唯物主义 / 结构批判 | 会把"个人选择"拧成"制度问题"，跟鲁迅的"横眉"正面冲突；也是**可见性演示**的最佳素材（他的句子最有分量） |
| **乔布斯** | `steve-jobs-skill` | 直觉主义 / 追随内心 | 与鲁迅是**最锋利的对立面**（"别活在别人的思考结果里" vs "从来如此，便对么"）；他本人**退过学**，被点名的戏剧性最强 |

**不选孔子的原因**：他不吵。三个人里有一个和稀泥的，信息层的效果就被稀释了。

> 备选阵容（若上面某位输出不稳定）：把马克思换成 **尼采**（`nietzsche-skill`，更极端），或把乔布斯换成 **雷军**（`leijun-skill`，更实务）。**鲁迅必须留**——他是被递刀的那个人。

### 3.2 议题

**公开议题（第一轮，用户公开发问）：**

```
我是大一，学商务英语。AI 已经能翻译能写作了，我该不该放弃这个专业，
去做我真正想做的事？请直接给答案，别和稀泥。
```

为什么这个议题好：
- **和作者真实身份绑定**（哈金院商务英语大一），评委一看就知道这是真问题。
- **AI 时代 + 教育 + 个人选择**三样都占，符合赛事的"应用场景"导向。
- 「**别和稀泥**」是关键的戏剧钩子：用户明确要求别打太极，而三位**因为互相看得见，还是会打太极**——观众的疑问（"他们怎么这么客气？"）就成了下一段悄悄话的动机。

**悄悄话（第二轮，用户私下对鲁迅说）：**

```
我私下问你：乔布斯那套"追随内心"，我一直觉得是幸存者偏差——
他退学是因为背后有沃兹尼亚克。你要是也这么想，就当面问他，别客气。
他不知道我跟你说了这些。
```

这句话的设计意图（**全片的核心机关，别改坏**）：
1. **给观点**（"幸存者偏差"）——给鲁迅一把具体的刀；
2. **给授权**（"就当面问他，别客气"）——把"点名拉人"的动机直接递到他嘴边，成功率大幅提高；
3. **给保密**（"他不知道我跟你说了这些"）——喂给模型"信息不对称"的语境，让措辞自然带出"只有我知道"的味道。

> 后端 `WHISPER_NUDGE_*` / `CHALLENGED_*` 已经在对收到悄悄话、以及被点名的角色下指令：**"当场点名相关的人，把他们之前的说法摆出来对质，但不要说「私下」「悄悄」这类字眼"**。所以只要前端把 `whisperTo` 传对了，这个效果是**机制推出来的**，不是配音演出来的。

预期输出（**三/四位都在打太极**，这就是我们要的）：
- 鲁迅："这得看你自己家里的条件……"
- 马克思："不能把它当成个人选择，这是一个结构问题……"
- 乔布斯："你应该去做你热爱的事……"
- 可能还有一句互相"我同意某某"的客套。

> **录屏时注意：这一段要完整保留**——三条回答的**开头两行**都要录下来（流式打字本身就是 SSE 在线运行的证据），中间模型思考的空窗期在剪辑时加速即可，**录的时候不要中断**。
>
> **如果他们不打太极、直接吵起来了**：这会让"信息层"缺少对照。**重录一轮**；或者删掉议题里的「请直接给答案，别和稀泥」，改成中性的「你们怎么看？」——冲突强度立刻下降，把冲突留给悄悄话之后再引爆（**这样其实更好看**）。

| 你要做的 | 屏幕上会出现的 |
| --- | --- |
| 1. 鼠标滚轮**上翻**看历史 | 画面往上滚，右下角浮出「**↓ 回到最新**」 |

> **录屏时注意：这一段要完整保留**——"上翻 → 出现按钮 → 点回底部"是 v1 更新日志里的真实功能，一个连续动作就证明两个更新点。

#### 环节 4｜悄悄话（镜 4-4，16 秒）★ 全片最关键

| 你要做的 | 屏幕上会出现的 |
| --- | --- |
| 1. 鼠标移到输入框左侧，点「**悄悄说**」 | 弹出在座人物列表（鲁迅 / 马克思 / 乔布斯） |
| 2. 点「**鲁迅**」 | 按钮变成「悄悄说 · 鲁迅」；输入框边框变红 |
| 3. **Cmd+V** 粘贴悄悄话全文 | user 气泡出现，右上角红标「**仅 鲁迅 可见**」（深红边框，和公开气泡的纯黑明显不同） |

> **录屏时注意：这一段要完整保留**——从点「悄悄说」到鲁迅回复的**全流程一秒不许跳**，中间的粘贴和回车停顿也要留着（这是最有说服力的 2 秒）。剪辑时可整体加速，但**不能切断**。
>
> **声音设计**：旁白说到"看不到"时，BGM 降到 -32 dB 或全静，只留鼠标点击声——全片最有效的一处留白。

#### 环节 5｜可见性（镜 4-5，12 秒）

| 你要做的 | 屏幕上会出现的 |
| --- | --- |

预期效果：**同一张桌子上，三个人拿着三份不同的信息**——鲁迅知道"幸存者偏差"那句，乔布斯被单独问过马克思的话，马克思什么都没被告知。剪的时候给"鲁迅的沉默"留 1 秒空镜，**让沉默被看见**。

> **录屏时注意：这一段要完整保留。**
>
> ⚠️ **一个必须知道的技术边界**（不然会拍废）：后端把 **assistant 发言强制设为 public**（route.ts 第 253–256 行注释写明）。所以**不能**把"马克思说的那句话"设成"仅乔布斯可见"——只能把你**自己（用户）的发言**设成仅某人可见。本剧本第 3 步就是按这个边界设计的（"马克思刚才那句，你怎么看？"是**你的问句**受限可见，马克思的原话本来就公开）。若你要演示"AI 发言只对部分人可见"，必须先改后端，别在镜头前硬演。

**预期乔布斯的回应**（被拉进讨论、正面接火）：

> "你不知道我退学之后那七个月是怎么过的……我退学不是因为勇敢，是因为我终于可以不再上我不感兴趣的课。"

**预期马克思的介入**（把话题拉回结构）：

> "你们两个争的是个人选择，可它从来不是——这是劳动力市场在给教育定价。"

| 你要做的 | 屏幕上会出现的 |
| --- | --- |
| **什么都不要做，让回复自己流完** | 鲁迅回复中点名「乔布斯」；若前端做了红章，出现「**已点名 乔布斯**」；随后乔布斯正面回应；马克思插话 |

>
> **声音设计**：点名前给 0.5 秒"吸气式"留白（BGM 全掉），名字出现时一记弦乐上挑（-18 dB）。

### 3.4 如果 AI 不按预期走：三种补录法

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| **鲁迅不提乔布斯**，只泛泛谈"幸存者偏差" | 悄悄话的"授权"信号不够强 | ① 先重录一遍（温度 0.85，本来就有随机性）；② 仍不行就把悄悄话改成更硬的版本：`你要是也这么想，就当面问他。别客气，我就在这儿看着。`；③ 再不行把轮次加到 **3**，给他第三轮开口的机会 |
| **乔布斯不接火**，继续讲自己的道理 | 乔布斯人格是"强锚定本人"，不容易被带走 | 接受这个结果——**他"讲自己的道理"本身就是真实反应**，反而更可信。把旁白 4-6 换成 §5.4 的备用句 |
| **三个人第一轮就吵起来**，没有"客套"对照 | 议题攻击性太强 | 删掉「请直接给答案，别和稀泥」，换成中性的「你们怎么看？」；冲突留给悄悄话之后再引爆 |

**通用保险：同一段圆桌录 3 遍**，挑对峙最充分的一遍。AI 输出不确定，这是成本最低的质量控制。**每一遍都要从头录完整流程**（不要只重录中间一段，否则气泡的上下文对不上）。

## ④ 录制与剪辑注意事项

### 4.1 录屏参数

| 项 | 设置 | 理由 |
| --- | --- | --- |
| 分辨率 | **1920×1080**（想要更清晰就录 2560×1440，导出时缩到 1080p） | 1080p 是安全选择；1440p 采集再缩，报纸风小字更锐 |
| 帧率 | **30 fps** | 这不是游戏画面，是文字流式输出 + 网页滚动，30 fps 完全够，文件还小一半。除非要做高速滚动镜头才用 60 fps |
| 系统声音 | **不录** | 网站本身没有音效；录进来只有通知声和风扇声，全是垃圾 |
| 麦克风 | **不录**（旁白另外单独录） | 别指望一边操作一边深情念稿，而且鼠标声会串进去 |
| 工具 | **OBS**（推荐）或 macOS 自带 `Cmd+Shift+5` | OBS 更稳：固定 1080p30、CQP 20、关键帧 2 秒、只采"窗口采集"（不录整个桌面） |
| 浏览器缩放 | `Cmd+0` 恢复 100%，再按 **`Cmd +`** 调到 **110%** | 报纸风小字在 1080p 里需要放大才看得清；但**地址栏必须还在画面里** |
| 鼠标指针 | 系统设置里把指针调大一点，打开"摇动以定位" | 评委要能跟上鼠标 |
| 光标移动 | **慢**。点前停 0.5 秒，点后停 0.8 秒 | 让评委看清"点了哪个按钮"——这是"可操作性"评分的直接来源 |

### 4.2 录屏前 10 项检查（每录一段前都过一遍）

1. 通知：开**勿扰模式**（`Option` 点右上角菜单栏图标），或干脆退出微信/QQ/Slack。
2. 书签栏：`Cmd+Shift+B` 隐藏，别让个人书签露脸。
3. 标签页：**只留一个标签**（outgate.chat），关掉其他所有窗口。
4. 地址栏：**必须是 `outgate.chat`**，不许出现 `localhost:3000` 或 `:3100`——出现就等于告诉评委"没上线"。
5. 缩放：`Cmd+0` → 110%。
6. 登录状态：**不登录**（作品卖点就是"免登录"）。
7. 对话干净：点聊天头右侧「**＋**」开新对话，别把上一轮测试残留录进去。
8. API Key：设置里确认**是空的**（走默认免费通道）——顺便证明"免费能用"。
9. 网速：先随便发一句跑通，确认没有超时（默认通道偶尔会慢）。
10. 盘位：录 1080p30 约 1GB/10 分钟，预留 10GB 空间。

### 4.3 章节次序与剪辑骨架

**先定旁白，再剪画面。** 顺序：

1. **先把旁白录成一条完整音轨**（或按镜分 8 段录），在剪映里**按分镜表的时间码铺到时间轴上**——这条音轨就是骨架，所有画面长度服从它。
2. 剪映里用 8 个文件夹/标记分隔 8 章，每章一个颜色标签。
3. 铺画面顺序（就是脚本顺序）：1 → 8，**不要打乱**。评委的注意力是线性衰减的：钩子在前、冲突在中段（**4-4 悄悄话在 02:06，4-6 点名在 02:34**，这是观众注意力第二高峰）、原创贡献落点在最后、结尾干净。
4. 每个画面片段**掐头去尾**，只留动作本身：粘贴动作加速 2×–4×，"等待 AI 回答"的空窗加速 4×–8×。
5. 全片不要出现超过 **1.5 秒**的静止无变化画面（除 4-7 的刻意留白和 8-1 片尾）。
6. 加字幕（见 4.4）→ 加 BGM（见 4.5）→ 调音（人声 -3 dB 左右，BGM -22 ~ -26 dB）。

### 4.5 BGM 与音效

- **BGM 选什么**：低沉大提琴/钢琴 + 留白的 **无版权**曲目。B站/小红书发布可用平台曲库；**竞赛提交建议用剪映"音乐"里的免费商用曲，或干脆不用 BGM**（评委连着看几十份，安静反而醒目）。
- **音量**：人声 **-3 dB** 左右；BGM **-22 ~ -26 dB**；
  - **01:16–02:56 演示段**：BGM 降到 **-30 dB 以下**（要能听清 AI 输出的节奏）；
  - **02:06–02:22 悄悄话**：全静或 -32 dB，只留鼠标点击声——**全片最有效的声音设计**；
  - **02:34–02:50 点名对峙**：点名前 0.5 秒 BGM 全掉，名字出现时弦乐上挑。
- **音效（都用剪映自带免费音效）**：
  | 时点 | 音效 | 音量 |
  | --- | --- | --- |
  | 每次点击按钮 | 轻"咔"（0.1s） | -22 dB |
  | 3-1 展开更多角色 | 轻"哗" | -22 dB |
  | 4-3 太极句放大 | 轻"咚" | -20 dB |
  | 4-5 红标「仅 乔布斯 可见」出现 | **印章落下**重音 | -18 dB |
  | 4-6 点名瞬间 | 弦乐短促上挑 | -18 dB |
  | 音效总数 | **不超过 8 处** | 多了就廉价 |
- **版权**：竞赛提交的视频**不要用流行歌**。你 B站发过的那条推广视频如果用了歌，**不能**直接剪进参赛版。

### 4.6 片头片尾

- **片头（就是第一章，不加独立片头）**：**绝对不要**做 AE/概念动画片头。赛事规则明确禁止"用概念动画替代真实成果"，一个华丽的动态片头会立刻让评委提高警惕。用真实首页加载 + 大字「门外谈」+ 副标 + 一道红线横划（≤1.5 秒）即可。

## ⑤ 备用方案

> **原则**：赛事规则「不得用概念动画或未实现的功能效果替代真实成果」。所以备用方案的**唯一合法形态**是：**删掉没做的功能，或者用已有的真实机制完成等价演示**。任何"UI 假界面、P 图、AE 弹窗"都是造假，不要碰。

### 5.1 方案 A（**首选**）：先把前端补完，再录

前后端**都已经写完并提交**，第 4 章可以原样完整开拍。

**验收测试（录之前必须过）：**
1. 开浏览器控制台 Network，发一条悄悄话给鲁迅 → 请求体里必须能看到 `"whisperTo":"luxun"`。
2. 同一轮里，马克思和乔布斯的回复**任何一句都不能出现悄悄话里的内容**（如"幸存者偏差""沃兹尼亚克"）——如果出现了，说明服务端过滤没生效，**停下来查，别录**。
3. 鲁迅的回复里**不能出现「私下」「悄悄」**这类字眼（后端提示词明确禁止）；出现了也不致命，但重录一遍更好。

### 5.2 方案 B：只录做完的那一部分

如果时间只够做一半：

| 做到哪一步 | 怎么改脚本 |

| 只有「可见性」，没有「悄悄话」 | 4-4 改成：把自己的发言设成"仅 鲁迅 可见"，再问他同样的质疑。**效果会弱一些**（缺少"另外两人看不到"的对照），但依然是真实的信息不对称 |
| 两个都没做，但后端在 | 见方案 C |

### 5.3 方案 C：v2 完全不能用时，用 v1 真实机制完成等价演示

**思路**：v1 本来就支持"1 人对谈"和"多人圆桌"两种模式，而**两种模式的历史是分开的**——这天然构成信息差，而且**全部是真实发生的**，没有一处是演的。

**替换镜 4-4 + 4-5，改成三段（共 44 秒，正好抵掉 4-4 16s + 4-5 12s + 4-7 6s 的时间，再加 10 秒）：**

| 新镜号 | 时间码 | 时长 | 画面内容 | 旁白文稿 |
| --- | --- | --- | --- | --- |
| 4-4' | 02:06–02:18 | 12s | 模式切到「**对谈**」（只留鲁迅一人）→ 输入：`我私下问你：乔布斯那套"追随内心"，我一直觉得是幸存者偏差——他退学是因为背后有沃兹尼亚克。你怎么看？` → 回车 → 只有鲁迅回答 | 我先单独问鲁迅一句——**这段对话，只有他一个人看得到**。 |
| 4-4'' | 02:18–02:32 | 14s | 点「**＋**」开新对话 → 切回「**圆桌**」（鲁迅 + 马克思 + 乔布斯入席）→ 重新抛出同一个议题 → 三条回答里，**鲁迅明显带着上一段对话的立场**（是否出现点名，看实际输出） | 然后我回到圆桌，把同一个问题再问一遍。鲁迅开口的时候，带上了刚才那段对话——**另外两位不知道，他这句话是从哪来的**。 |
| 4-6' | 02:32–02:56 | 24s | 圆桌回复全景（时间加长，把三条回答都留完整） | 重点来了——同一张桌子，**信息不一样，态度就不一样**。信息不对称，才是矛盾的真正开关。 |

**这样做的合规性说明（**务必照着写进作品介绍文档**）**：
- 画面里出现的**只有 v1 真实存在的按钮**：`对谈`、`圆桌`、`发言`、`＋`、模式切换。没有任何伪造的界面元素。
- 旁白说的是**真实发生的事情**："我先单独问了他一句，这段对话只有他看得到"——这是事实，不是比喻。
- **不得**在旁白、字幕或文档里说"本站支持悄悄话""每条发言可设为仅某人可见"。要改成："v2 正在把信息隔离做进圆桌——当前版本可以用'单人对谈 + 圆桌'实现同样的信息差。"
- 评分影响：核心创新的演示从"机制直接可见"降级为"机制可推导"，会吃亏，**但不会被判造假**。所以方案 A 永远优先。

> 三句合计 **107 字**，替换掉原来的 47+43+51 = **141 字**，全片从 907 字降到约 **873 字**——此时**不要补新话**，宁可让 4-7 的留白延长到 10 秒，画面更容易被记住。

### 5.5 如果不想露脸（7-1 替代方案）

合法，且不影响"原创贡献"的落点，但要保证**人确实在场**：
- 拍**手 + 桌面**：手在键盘上敲，屏幕上是代码/网站；配同样的旁白。
- 或拍**环境 + 屏幕**：一张书桌、一盏灯、屏幕亮着 outgate.chat，镜头缓慢推近，旁白照念。
- **不要**用网图、素材视频里的"程序员背影"——那反而会被认为不是本人作品。

**但首选还是露脸 12 秒。** 赛事明确要"学生原创贡献"，一张真人脸加一句"我不是科班出身"的说服力，抵得上两分钟功能演示。你做过校宣传部报道组，上镜不会比这更难。

### 5.6 通用兜底

- **AI 服务不稳定**（默认免费通道偶发超时）：录屏前先跑 3 次热身；若录制当天一直超时，切到设置里填**你自己的** DeepSeek Key（画面上把 Key 输入框打码或用剪映遮挡），并在旁白里不提"默认免费通道"那句（改成"支持自带 API Key"）。

- **旁白录砸了**：不要将就。旁白是全片的骨架，重录一遍的成本远低于剪一版废片。
